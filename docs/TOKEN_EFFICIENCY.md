# 自动注释 token 优化

## 已实现

- 自动模式下，单个 `propose_wizard_actions` 调用通过检查、报告 ready 且无 issues 后，直接结束后端模型循环。混合工具批次、被拒绝动作、缺失报告、blocked 和手动模式继续原流程。前端应用、有限修复和最终模板校验照常执行。
- `/sdrf-annotate` 只注入当前步骤的专用流程；通用规则原文保留。Samples 同时保留旧 characteristics 与 samples 两节。未知标题保留，避免新增规则被静默丢弃。
- 工具结果、完整 PRIDE 缓存和快照中的 JSON 使用紧凑分隔符，不删字段、不截断证据。
- 自动请求的历史反馈仅在卡片已应用、无错误/回滚状态、参数与当前快照完全一致且后端完整渲染时，引用当前状态替代重复参数。仅覆盖样本数、技术模板、质量容差，以及未截断的名称/重复编号数组。复杂动作、旧值、失败或待执行动作保留完整参数；手动请求保留原反馈。
- 修正自动模式中“不会自动修复”的旧说明，与现有有限参数修复流程一致。

## 用量记录

每次完成结果的 `trace` 增加：

- `llmRounds`：实际模型调用轮数。
- `stoppedAfterReady`：是否省去成功提案后的模型收尾轮次。
- `llmRoundMetrics`：每轮序号、`messageChars`、`toolSchemaChars`、服务商原始 `usage`。

字符数是紧凑 JSON 序列化字符数，不是 tokenizer 或计费 token。usage 未返回时为 null，不能按零用量处理。服务商返回的缓存/推理 token 明细原样保留；每轮保留最后一次 usage，避免累计式流片段重复计数。

兼容网关默认不发送新的请求参数。确认服务商支持后，在后端环境设置 `LLM_STREAM_INCLUDE_USAGE=true` 并重启，才会发送 `stream_options.include_usage=true`。无论该开关是否启用，服务商主动返回的 usage 都会被读取，包括 choices 为空的尾部事件。不为探测兼容性重发付费请求。

## 本地量化

仅技能按步骤筛选就减少每轮固定输入：

| 步骤 | 原技能字符数 | 优化后 | 减少字符数 | 相对原系统+技能+工具定义+步骤说明 |
|---|---:|---:|---:|---:|
| setup | 19,717 | 10,891 | 8,826 | 13.9% |
| samples | 19,717 | 11,629 | 8,088 | 14.2% |
| runs-files | 19,717 | 9,051 | 10,666 | 19.0% |
| protocol | 19,717 | 12,170 | 7,547 | 13.3% |

以上不包括项目证据、历史、动态快照、自动执行说明和 proposal 工具；不是总 token 降幅。符合终止条件的成功提案另外省去原先的收尾模型调用。

## 验证与边界

新增测试覆盖成功/无动作提前结束、手动模式、证据阻塞、动作拒绝、混合工具、缺少报告、usage-only 流事件、网关参数开关、完整保留当前技能规则，以及历史参数在回滚/值变化/截断时不被删除。

科学质量仍需相同模型、相同输入项目的真实 A/B 验证；本次没有运行付费批量注释，不能据单元测试宣称真实完成率或科学正确率完全相同。不削减论文/PRIDE 证据、不降低模型、不取消本体或模板验证。更激进的跨步骤证据摘要和工具裁剪尚未实施。

## 思考强度配置

`LLM_REASONING_EFFORT=low` 在请求中发送 `reasoning_effort: "low"`，保留 DeepSeek 默认开启的思考模式。支持 low/high/max；空字符串不发送此参数，保持服务商默认行为与其他网关兼容。本地 backend/.env 已设为 low，修改后需重启后端。该设置不改变模型单价，实际用量与注释质量需要重新测量；历史 20 项目报告对应调整前的设置。
